    Os arquivos que a montagem usa, em src/components. A letra liga o arquivo à camada: P é primitivo, F é composição, E é o específico, T é a tela.

    Uma caixa dentro da outra é composição: quem contém quem. O nome em cima é a peça e o cinza embaixo é o arquivo ou o pacote de onde ela vem.

    A base não conhece exames. Cada primitivo embrulha uma peça de biblioteca ou HTML: a busca vem do HeroUI, a tabela é table com DnD.

    TextCard escolhe entre Textarea e Input por singleLine; os modos edit e preview já vêm no contrato.

    columns: UniversalTableColumn[] data: UniversalTableItem[] mode?: UniversalTableMode isReadOnly?: boolean enableDnD?: boolean

    Busca e tabela formam um bloco sem domínio clínico. Duas listas entram por props separadas: searchItems alimenta a busca e tableItems, a tabela.

    o bloco acrescenta: duas listas, uma só borda TSearch extends object TItem extends { id: string } searchItems?: TSearch[] tableItems?: TItem[] columns?: UniversalTableColumn[] onTableItemsChange?: (items: TItem[]) => void

    BaseEditableCard é dono da anatomia: cabeçalho com título e operações, corpo e rodapé. O corpo é só um lugar, children; quem o preenche é outro.

    o único lugar aberto title: string onTitleChange?: (value: string) => void headerActions?: readonly EditableCardAction[] children: ReactNode cardFooter?: ReactNode titleMode?: CardTitleMode

    PrescriptionBaseCard põe o bloco dentro do shell. A tabela vem primeiro e o children da feature entra depois, no mesmo corpo. Não há herança de classe.

    o bloco entra no corpo do shell <BaseEditableCard title={title} onTitleChange={onTitleChange} > <AutocompleteTableBlock {...autocompleteTableProps} /> {children} </BaseEditableCard>

    CardExamePrescricao traz o domínio: exames. Passa as props do bloco e preenche o slot com uma Section de orientações, que existe em edição ou quando há texto.

    Os três modais ficam ao lado, irmãos no Fragment, fora do card.

    o domínio entra pelo children {showObservacoes && ( <Section label={ORIENTATIONS} > <TextCard value={obs} /> </Section> )}

    ExamesMain monta a tela do paciente. MainGenericEditor dá o shell do editor, ExamesCardsBody faz a lista em SmartGrid, e cada item vira um CardExamePrescricao.

    O código renderiza items; o número de cards não é fixo.

    a lista decide quantos cards <CardExamePrescricao item={item} markers={markers} onChange={(updated) => handleItemChange(i, updated)} isReadOnly={bodyReadOnly} />
